## 1. 文档用途与产品结论

本文用于回答 ChordSheet V1 为什么存在、由哪些部分组成、用户怎样完成一次制谱和演奏、页面应怎样表现，以及什么结果才算完成。产品需求与页面设计合并在本文中，避免把同一项交互拆成两份权威说明。数据字段以 `schema/chordsheet.schema.json` 为准，模块划分和开发顺序以 `docs/versions/v0.1.0/implementation-v0.1.0.md` 为准。

ChordSheet V1 由两个独立但共享数据契约的交付物组成：AI Agent 将原始材料整理为 `.chordsheet` 谱包；本地显示工具导入谱包，负责阅读、修正、转调、指法显示和导出。显示工具不直接调用多模态模型，也不要求用户提供 API Key。

## 2. 用户问题与产品目标

### 2.1 用户问题

用户通常从吉他谱网站找到已经包含歌词、和弦和换和弦位置的谱子，但原网站可能包含广告、付费限制或受限的转调功能。把内容复制到普通文本后，空格和换行容易变化，和弦不再稳定地对应歌词中的换和弦位置；直接保存 PDF 或截图又无法编辑、转调或适配手机屏幕。

ChordSheet 要保留原谱中真正影响演奏的信息，同时去除原网页的展示限制。它不把截图或 PDF 当作最终页面，而是重新生成结构化、可缩放的实时电子谱。

### 2.2 产品目标

V1 必须完成以下闭环：

1. 接收复制文字、截图和 PDF 中的一种或多种材料；
2. 恢复歌词、和弦、段落及和弦对应的歌词位置；
3. 生成可以被显示工具稳定读取的 `.chordsheet` 谱包；
4. 在桌面和手机上生成清爽、适合演奏的实时谱面；
5. 允许用户修正自动结果，并在不破坏歌词锚点的情况下转调；
6. 使用经过核验的吉他指法，不用推测数据填补缺失指法；
7. 将最终结果导出为 PDF 或可再次导入的 `.chordsheet`。

### 2.3 核心质量原则

和弦与歌词位置的正确关系是 V1 的最高优先级。页面美观、自动转调和指法图都不能以牺牲锚点正确性为代价。

系统不得用页面像素坐标保存歌词和和弦关系。每个歌词上方的和弦必须锚定到该歌词行的 Unicode 字素边界，使屏幕宽度、字号和换行变化时仍能保持语义位置。原截图或 PDF 中的视觉坐标只作为 Agent 判断和回查的证据，不作为最终排版依据。

## 3. 产品组成与责任边界

### 3.1 两个交付物

| 交付物 | 输入 | 主要责任 | 输出 |
|---|---|---|---|
| AI Agent 核心与 Codex Skill | 复制文字、截图、PDF、用户的原始材料保留选择 | 理解材料、解决来源冲突、建立锚点、标记不确定结果、校验并打包 | `.chordsheet` |
| ChordSheet 本地显示工具 | `.chordsheet` | 本地曲库、实时渲染、人工修正、转调、Capo、指法与导出 | PDF、更新后的 `.chordsheet` |

两个交付物通过同一份数据契约通信。Agent 不能依赖显示工具内部状态生成私有字段，显示工具也不能依靠某个特定模型才能解释谱包。

### 3.2 Agent 的交付形态

V1 使用一套与平台无关的 Agent 核心规则，正式提供 Codex Skill 适配。ChatGPT 使用同一套来源优先级、锚点规则、Schema 和验收规则，不维护第二套产品逻辑。平台差异只影响文件上传、脚本调用和成品交付方式。

### 3.3 本地工具的边界

本地工具不建立账号、不连接云端曲库，也不负责多端同步。导入的谱子保存在当前设备；需要在另一台设备使用时，用户手动导出并重新导入 `.chordsheet`。PDF 用于任何设备上的只读查看，不能替代结构化谱包。

## 4. 完整使用流程

### 4.1 从原始材料生成谱包

1. 用户向 AI Agent 提供复制文字、截图、PDF 中的一种或多种材料；同一种材料可以有多份。
2. 用户选择是否把原始文字、截图和 PDF 嵌入最终谱包。未嵌入时，谱包仍可保存来源类型和文件名等必要记录。
3. Agent 检查标题和调弦；来源没有给出时，先向用户确认这两个必需字段。
4. Agent 读取全部材料，区分内容证据与位置证据，并建立歌曲元数据、段落、歌词行、和弦事件和歌词锚点。
5. Agent 对冲突或无法确定的结果作出最可能判断，同时把相关项目标记为低置信且未复核。低置信结果不能阻断整首歌曲生成。
6. Agent 按 `schema/chordsheet.schema.json` 校验根数据文件，并生成 `.chordsheet` ZIP 归档。
7. Agent 交付谱包和一份简短结果摘要，说明是否包含原始材料、低置信项目数量和校验结果。

### 4.2 在本地工具中完成谱子

1. 用户导入 `.chordsheet`；工具先检查归档安全、格式版本、Schema 和跨字段语义。
2. 校验通过后，歌曲进入当前设备的本地曲库。相同 `documentId` 已存在时，工具要求用户确认替换，不能静默覆盖。
3. 用户在阅读模式检查谱面。低置信提示保持低干扰，但可以逐个定位。
4. 需要修改时，桌面端进入编辑模式，修正歌词、和弦、段落或锚点；修改自动保存到本地曲库。
5. 用户设置转调、Capo、字号和和弦显示方式，工具即时更新谱面。
6. 用户导出当前阅读状态的 PDF，或导出包含最新修改的 `.chordsheet`。如果谱包原本包含原始材料，导出时允许选择保留或移除这些材料。

## 5. AI Agent 产品要求

### 5.1 支持的输入组合

Agent 必须接受以下任意组合，而不是要求三种材料同时存在：

- 从网页或 PDF 复制的歌词与和弦文字；
- 一张或多张原谱截图；
- 一份已经排版的 PDF 谱。

只有文字时，Agent 仍需根据空格、换行、段落标记和上下文建立最可能的锚点。只有截图或 PDF 时，Agent 需要同时识别内容和位置。多种材料同时存在时，Agent 必须综合使用，而不是只读取其中一种。

### 5.2 来源优先级

不同来源按信息维度分工：

1. 清晰的复制文字优先提供歌词拼写和和弦名称；
2. 截图优先提供和弦位置、段落边界及视觉关系；
3. 没有截图时，Agent 将 PDF 页面渲染为图片，并以渲染结果判断位置；
4. 复制文字与视觉材料冲突且无法可靠消解时，Agent 采用最可能结果并标记冲突，不能隐藏分歧；
5. 同时存在截图和 PDF 时，截图是位置判断的最高优先级证据。

### 5.3 识别与结构化

Agent 必须识别歌曲标题、歌手、书面调、调弦、Capo 和难度等可用元数据，但不得为了填满字段而推测不存在的信息。标题与乐器调弦是谱包必需信息；来源没有给出时，Agent 必须向用户确认后再完成打包，不能静默假定标准调弦。其余元数据无法确认时可以省略。

`metadata.baseWrittenKey` 始终表示谱面所写和弦对应的基础调，不表示经过 Capo 后的实际发声调。来源只标出实际调和 Capo 时，Agent 用“实际调下移 Capo 半音数”得到基础书面调，并与谱面和弦交叉检查。The Cure 验收样例中的 `Key: Db` 与 `Capo: 1st fret` 因而保存为 `baseWrittenKey: C`、`view.capo: 1`；来源信息互相矛盾时省略基础书面调并在交付摘要记录冲突，不能保存一个会导致实际调计算错误的确定值。

正文需要区分段落、歌词行、纯和弦行和注释行。歌词行中的每个和弦都必须保存原始和弦符号及字素偏移；前奏、间奏等没有歌词的部分按纯和弦行保存。段落名称保留来源中的编号和语义，例如 `Verse 1`、`Chorus` 或自定义标签。

### 5.4 不确定结果与复核状态

置信度使用 `high`、`medium`、`low`，复核状态使用 `unreviewed`、`confirmed`、`corrected`。低置信且未复核的项目在编辑模式中显示提示；用户确认或修正后，提示消失但复核状态继续保存在谱包中。

以下情况至少应降低置信度并记录原因：

1. 多种来源的和弦名称或位置不一致；
2. 截图模糊、裁切或遮挡关键位置；
3. PDF 渲染后无法判断某个和弦对应的具体歌词字素；
4. 复制文字已失去排版，只能根据语义推断位置；
5. 段落名称或重复关系只能从上下文推断。

### 5.5 Agent 失败状态

Agent 不能生成 Schema 有效的数据时，不得交付伪装成成功的谱包。它应指出无法生成的具体原因，并尽量保留已经完成的结构化草稿供用户补充材料。单个位置不确定不属于整体失败，应按低置信流程继续生成。

## 6. `.chordsheet` 产品契约

`.chordsheet` 是 ZIP 归档，根目录必须包含一个 UTF-8 编码的 `chordsheet.json`。该文件的唯一字段权威是 `schema/chordsheet.schema.json`。可选原始材料只能放在 `sources/` 下，并由 `chordsheet.json` 中的来源记录引用。

结构化数据必须覆盖以下产品信息：

1. 格式版本、稳定文档 ID 和歌曲元数据；
2. 当前转调、Capo、字号和全谱指法显示状态；
3. 来源类型、角色及是否嵌入原始文件；
4. 段落、歌词行、纯和弦行、注释行和复核状态；
5. 歌词和弦的字素锚点及可选来源证据；
6. 经过核验的可选吉他指法；
7. 可选拍号、速度和扫弦节奏数据。

V1 的显示工具不展示节奏数据，但导入、保存和重新导出时不得丢失这些字段。谱包不允许依赖外部 URL 才能完成基本渲染。

## 7. 本地曲库与文件管理

### 7.1 曲库首页

曲库首页只承担歌曲管理，不在首页复制完整谱面。空状态以“下载制谱 Skill、生成 `.chordsheet`、导入阅读”的两步路径说明来源，并提供实际的 Skill ZIP 下载、点击选择与拖入 `.chordsheet` 的导入入口。拖入 PDF、截图或文字时，页面必须说明它们需要先由 Skill 整理，不能暗示本地工具会识别原始材料。非空状态按歌曲标题和歌手显示本地条目，支持打开、删除和导入新谱包。

删除歌曲必须经过确认，并说明本地未导出的修改会同时删除。V1 不提供回收站或云端恢复。

### 7.2 导入状态

导入结果分为四类：

| 状态 | 页面行为 |
|---|---|
| 有效的新谱包 | 保存到本地曲库并打开阅读页 |
| 相同 `documentId` 已存在 | 显示替换确认；用户取消时不修改现有数据 |
| 格式版本不支持 | 拒绝导入并显示检测到的版本和当前支持版本 |
| 归档、Schema 或语义校验失败 | 拒绝导入并指出可定位的错误路径，不保存半成品 |

缺少可选来源文件、节奏数据或指法数据不属于导入失败。来源记录声明文件已嵌入但归档内不存在对应路径时，属于无效谱包。

### 7.3 本地保存与导出

正文修改和阅读设置都自动保存到当前设备。保存失败时页面必须立即提示，不能继续显示“已保存”。

本地曲库属于当前浏览器、浏览器配置和应用来源的站点数据。清除站点数据、换浏览器或改用另一个应用地址都不会自动带回曲库；页面需要提醒用户定期导出重要谱包，V1 不提供云端恢复。

导出 `.chordsheet` 时保存当前正文、复核状态和阅读设置。如果原始材料存在，用户可以选择保留或移除；选择移除后，来源记录保留必要元数据，但不再声明文件已嵌入。

## 8. 实时谱面设计

### 8.1 视觉原则

页面参考用户提供的 The Cure PDF 的核心编辑特征：黑白、高对比、左对齐、明确的歌曲信息和段落层级，以及和弦在歌词上方的直接关系。在此基础上优化响应式阅读和操作反馈，不复制原网站广告、导航或品牌元素。

页面不得依靠渐变、大量圆角卡片、装饰图标或无用途动画制造层次。主要层次来自字体、字号、字重、留白和细分隔线。桌面端保持接近纸质谱的阅读节奏；手机端允许自然换行，但和弦必须跟随锚点重新排布。

### 8.2 阅读页信息结构

阅读页按以下顺序组织：

1. 歌曲标题与歌手；
2. 难度、调弦、书面调、Capo 和实际发声调；
3. 本曲使用的和弦概览；
4. 转调、Capo、字号、指法显示、编辑和导出操作；
5. 按原顺序排列的段落与实时谱面。

节奏型即使存在于谱包中，V1 阅读页也不显示。页面不能出现一个空的节奏区域。

### 8.3 和弦与歌词渲染

歌词以自然文本排版；和弦渲染在所锚定字素之前的上方。多个和弦不得通过固定空格字符串定位。窄屏换行时，布局引擎按锚点把歌词和相应和弦一起分配到新行，不能把和弦留在上一行、歌词移到下一行。

低置信提示在阅读模式中只使用轻量视觉标记，不改变和弦文字或歌词内容。用户可以从提示进入对应位置的检查操作。

### 8.4 全谱指法显示

阅读模式下点击任意和弦，整首谱和顶部和弦概览同时在以下两种状态间切换：

| 状态 | 显示内容 |
|---|---|
| `name` | 只显示和弦名称 |
| `nameAndDiagram` | 每个和弦同时显示名称和已核验指法图 |

再次点击任意和弦恢复名称模式。工具栏也提供同一全局开关，保证键盘和触屏用户可以明确控制状态。

编辑模式下点击和弦用于选择和编辑，不能同时触发全谱切换；此时只通过工具栏改变指法显示。转调后，顶部概览、正文和指法查询必须使用转调后的和弦名称同步更新。

谱包或本地指法库没有经过核验的对应指法时，全谱指法模式显示和弦名称和“暂无指法”，不得绘制推测图形。指法图的弦顺序、品位、闷弦、空弦、手指和横按信息必须来源明确。

标准 EADGBE 定弦的内置库可以保存同一和弦的多个可选按法；页面默认显示低把位、低跨度的一个。谱包中的来源指法在未转调时优先于内置库；转调后按转调后的和弦名称重新查询内置库，不能复用原调来源图。

### 8.5 转调与 Capo

用户可以按半音升降整首歌，也可以选择目标书面调。转调只改变渲染结果，不直接覆盖谱包中保存的基础和弦，因此“恢复原调”必须精确返回修正后的基础谱。

只有已知基础书面调时才提供目标调选择；基础书面调未知时仍可按半音升降和弦，但页面继续显示“实际调未知”，不能从和弦集合自动猜测歌曲调性。

转调遵守以下规则：

1. 保留和弦性质和全部后缀；
2. Slash chord 的根音和低音分别转调；
3. 歌词、段落和字素锚点不移动；
4. 根据目标调选择一致、易读的升降号拼写；
5. 无法安全解析的符号保持原样并提示，不得部分改写成错误和弦。

Capo 只允许手动设置，工具不推算推荐品位。改变 Capo 不改写书面和弦。已知书面调时，页面显示“实际调 = 当前书面调上移 Capo 半音数”；书面调未知时显示“实际调未知”，不能从个别和弦强行推测。

### 8.6 阅读设置与 PDF

字号调整影响实时页面，并保存到当前歌曲的阅读设置。导出 PDF 反映当前转调、Capo、字号和指法显示状态；编辑锚点、低置信提示、选中状态和来源证据不进入 PDF。

PDF 以清晰看谱为目标，允许按内容生成多页，不要求强行压缩为原 PDF 页数。分页不能把和弦与其歌词拆开，也不能把段落标题单独留在页尾。

## 9. 编辑模式

### 9.1 桌面端编辑能力

桌面端提供完整编辑模式，支持：

- 修改歌曲元数据、段落标签、歌词和和弦；
- 新增或删除段落、行和和弦；
- 将和弦拖动或移动到另一字素边界；
- 确认或修正低置信项目；
- 保存后继续转调和导出。

编辑模式中的和弦字段始终显示和修改基础和弦。进入编辑模式时，当前转调偏移被暂时隐藏但继续保存；返回阅读模式后恢复该偏移并重新计算显示和弦。这样可以避免把转调后的显示名称误写为基础谱。

拖动和弦时只能吸附到当前歌词行的字素边界，不能保存任意像素位置。修改歌词导致文本长度变化时，未受影响范围内的锚点自动跟随；落在被删除范围内的锚点收拢到删除起点，并标记为需要检查。

### 9.2 阅读与编辑状态分离

阅读模式隐藏锚点、编辑边框和批量操作，只保留演奏需要的内容。进入编辑模式后才显示锚点和复核提示。存在未保存修改时退出页面，工具必须先完成本地保存；保存失败时阻止静默离开。

### 9.3 手机端边界

手机端以阅读和演奏控制为主，支持转调、Capo、字号、全谱指法、查看低置信提示和 PDF 导出。V1 不在手机端提供歌词、和弦、段落及锚点的完整编辑入口；页面需要明确提示使用桌面端完成精细修改。

## 10. V1 范围

### 10.1 必须交付

| 范围 | V1 要求 |
|---|---|
| 多种输入 | Agent 支持文字、截图、PDF 单独或组合输入 |
| 自动对齐 | 建立歌词字素锚点，并标记无法确定的位置 |
| 实时谱面 | 桌面和手机响应式阅读，保持和弦语义位置 |
| 人工修正 | 桌面端完整编辑及复核流程 |
| 转调与 Capo | 整曲转调、恢复原调、手动 Capo 和实际调显示 |
| 和弦指法 | 全谱同步切换，只显示经过核验的指法 |
| 本地曲库 | 当前设备持久保存和自动保存 |
| 导入导出 | `.chordsheet` 导入、重新导出及当前视图 PDF |

### 10.2 暂不交付

以下能力不属于 V1：

- 显示工具直接识别原始文字、截图或 PDF；
- 产品内置多模态 API、API Key 配置或按次付费调用；
- 账号、云端存储、跨设备自动同步和协作编辑；
- 手机端完整谱面编辑；
- 节奏型和拍号的显示、编辑或教学；
- 自动推荐 Capo；
- 音频播放、节拍器、六线谱和社区功能。

节奏数据已经进入谱包契约，但这不构成 V1 显示功能，也不能因此增加空白页面区域。

## 11. 数据、隐私与版权

本地工具的曲库、编辑和导出默认在当前设备完成。除用户主动把谱包交给外部 Agent 外，显示工具不上传歌曲、歌词、截图或 PDF。应用可以从静态地址加载，但加载完成后的导入、阅读、编辑、转调、保存和导出不能依赖后端或持续联网。

原始材料是否嵌入谱包由用户决定。界面需要说明嵌入会增加文件体积，并可能包含受版权保护或带有个人信息的材料。移除原始材料不能删除已经结构化并由用户确认的谱面内容。

AI Agent 生成的结果不是事实保证。来源冲突、视觉模糊和推断位置必须通过复核状态表达，不能用自信文案掩盖不确定性。

## 12. 验收标准

### 12.1 谱包与 Agent 验收

1. Agent 能分别处理纯文字、纯截图、纯 PDF 和组合材料，并输出格式为 `1.0.0` 的谱包；
2. `.chordsheet` 可以解压，根目录存在唯一 `chordsheet.json`，且数据通过 Schema 和语义校验；
3. 组合输入遵守内容与位置的来源优先级，冲突项目保留原因和复核状态；
4. 用户选择不包含原始材料时，归档中没有对应文件；选择包含时，来源记录与归档路径一致；
5. 低置信项目不会阻止生成，并能在显示工具中逐个定位、确认或修正；
6. 用户提供的 The Cure 三页 PDF 是 V1 正式人工验收样例。Agent 生成的候选谱必须覆盖所有可见段落、歌词和和弦；清晰可判定的和弦必须位于与 PDF 相同的歌词字素，无法确定的项目必须标记为低置信；最终确认后的谱包必须达到全部可见和弦名称与锚点 100% 正确。

### 12.2 显示与编辑验收

1. 导入、编辑、自动保存、导出并重新导入后，歌词、段落、基础和弦、锚点、复核状态、可选节奏数据和阅读设置不丢失；
2. 桌面改变窗口宽度、手机改变方向或调整字号时，和弦仍跟随对应歌词字素；
3. 编辑歌词后，未受影响的锚点保持稳定；删除范围内的锚点进入需要检查状态；
4. 相同 `documentId` 导入时不会静默覆盖，本地保存失败时不会显示成功状态；
5. 手机端可以完成阅读、转调、Capo、字号和全谱指法切换，不出现精细编辑入口。

### 12.3 音乐功能验收

1. 半音升降、选择目标调和恢复原调均能处理根音、和弦后缀和 Slash bass；
2. 转调不修改歌词或锚点，恢复原调与修正后的基础和弦逐字符一致；
3. Capo 改变后书面和弦不变，实际发声调计算正确；
4. 点击任意和弦时，顶部概览和正文同时在名称与名称加指法之间切换；
5. The Cure 样例中的 Asus2、Cmaj7、Fmaj7、Dm、F、C、G/B、G 必须逐一与可靠来源或原 PDF 指法核验；
6. 缺少已核验指法时显示“暂无指法”，不允许用占位图冒充真实指法。

### 12.4 导出与本地性验收

1. PDF 与当前转调、Capo、字号和指法显示状态一致；
2. PDF 不包含编辑锚点、低置信标记、选择框或来源证据；
3. 分页不拆散同一和弦与歌词位置，段落标题不单独停留在页尾；
4. 在不调用外部 AI API 的情况下，本地工具可以完成导入、阅读、编辑、转调、保存和导出。

## 13. 已知风险与完成条件

### 13.1 已知风险

| 风险 | 产品处理原则 |
|---|---|
| 不同 Agent 的多模态理解存在波动 | 用同一核心指令、Schema、低置信状态和 The Cure 样例约束输出 |
| 复制文字与视觉材料发生冲突 | 按信息维度使用来源优先级，无法消解时保留冲突原因 |
| Unicode 文本编辑使字符索引变化 | 使用字素边界而不是 UTF-16 码元或像素位置 |
| 指法数据错误或许可不清 | 只接收可追溯的已核验数据；缺失时明确显示不可用 |
| 原始材料使谱包过大或包含敏感内容 | 由用户选择是否嵌入，并允许导出时移除 |
| ChatGPT 与 Codex 文件能力不同 | 平台适配只改变执行方式，不改变谱包与产品规则 |

### 13.2 V1 完成条件

V1 只有在两个交付物共同通过验收后才算完成：Agent 能生成有效谱包；本地工具能在桌面和手机完成规定范围内的读取与操作。只完成页面原型、只完成 Schema、只完成 Agent 或依赖人工修改 JSON 都不构成产品完成。

## 14. 当前实施状态

本节不重定义前述产品基线，而是记录截至首次实现完成时已经可运行的范围，以及仍须由 Simon 对照本 PRD 验收或决定的差异。实际测试、构建和未上线状态以 `docs/versions/v0.1.0/release-v0.1.0.md` 为准。

### 14.1 已实现并完成本地验证的范围

本地工具已实现 `.chordsheet` 的安全导入、首页点击选择或拖入谱包、浏览器本地曲库、响应式阅读、歌词字素锚点渲染、半音转调、手动 Capo、实际调显示、浏览器打印、谱包导出和桌面歌词行编辑。桌面编辑当前覆盖歌词文本、歌词行中的和弦名称、字素锚点以及歌词行和弦的新增、删除；修改文本时会按本文件规定标记受影响锚点。

`skills/chordsheet/` 已提供 Codex Skill，用同一份 Schema、来源优先级、低置信规则和打包命令指导文字、截图与 PDF 材料的制谱。工具在标准定弦下内置许可明确的 828 个和弦条目与 3,283 个按法，并保留 The Cure 参考包中 Asus2、Cmaj7、Fmaj7、Dm、F、C、G/B、G 的来源图优先级；它以 C 书面调加 Capo 1 显示 Db 实际调。

当前阅读界面以一张实心高对比谱纸作为唯一主表面，工具栏与曲库仅作为较轻的半透明操作层；层级主要依靠系统字体、留白和细分隔，而非装饰性渐变或卡片堆叠。所有可操作控件都有可见焦点和即时按压反馈，并为减少动态效果、减少透明度和提高对比度偏好提供样式降级。手机端保留转调、Capo、字号和全谱指法控制，不显示无效的精细编辑入口，改为提示用户在桌面端校正歌词或落点。

### 14.2 仍须在验收或后续实现中处理的差异

以下内容仍是 V1 基线的一部分，不能因已有可运行页面而视为完成：

1. 尚未使用 The Cure 三页 PDF 生成覆盖全部歌词、段落与锚点的完整 Agent 成品；当前参考包只用于核验元数据、Capo 和八张来源指法，不能替代第 12.1 节的全谱人工验收。
2. 当前编辑器不编辑歌曲元数据、段落标签、纯和弦行、注释行，也不新增或删除段落和行；阅读区的和弦在编辑模式仍触发全谱指法切换，尚未实现第 8.4 与第 9.1 节要求的“编辑模式点击和弦用于选择”。
3. 当前导出会保留已导入的嵌入来源，尚未提供“保留或移除来源材料”的用户选择。
4. 当前 PDF 功能调用浏览器打印并已检查打印样式；尚未完成实际导出 PDF 的逐页渲染验收，因此不能确认第 8.6 与第 12.4 节的所有分页条件。

这些差异同时记录在 Release，等待 Simon 决定是在当前 V1 补齐后验收，还是以明确的产品决策调整版本范围。本文已作为开发基线获批；在验收和发布决定前，Release 保持 `release-candidate`，不标记为已发布。
