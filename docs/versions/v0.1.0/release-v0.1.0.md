## 2. 实际完成的交付

### 2.1 谱包合同、校验与本地曲库

`.chordsheet` 使用根目录 `chordsheet.json` 与可选 `sources/` 的 ZIP 结构。导入器在解压前检查归档大小、条目数、中央目录、重复或不安全路径、加密和符号链接；随后执行 Schema、跨字段语义和可选来源摘要校验。导入成功后，文档和嵌入来源字节由 Dexie 保存到当前浏览器的 IndexedDB。

工具支持点击选择或主页拖入单个 `.chordsheet`，重复 `documentId` 替换确认、本地歌曲打开与删除、500 ms 自动保存、谱包重新导出和浏览器打印。拖入 PDF、截图或文字不会触发识别，而会提示先由 Agent 整理为谱包。它不要求账号、后端、API Key 或持续联网。

### 2.2 实时谱面、编辑、转调与指法

阅读页按字素锚点将和弦渲染在歌词对应位置上方，并在桌面与手机视口保留阅读、半音转调、目标书面调、手动 Capo、实际调、字号和全谱指法显示控制。浏览器打印样式会隐藏工具栏、编辑器和低置信提示。

当前视觉层级以一张实心高对比谱纸承载阅读内容，顶部工具栏和曲库使用较轻的半透明材质区分操作层；不使用装饰性渐变或卡片堆叠。按钮和拖放区提供即时按压、悬停、焦点与拖入反馈；减少动态、减少透明度和提高对比度的系统偏好均有对应降级。手机端保留转调、Capo、字号和全谱指法控制，隐藏不能完成工作的编辑入口，并明确提示到桌面端完成精细修正。

桌面编辑器当前可改歌词、歌词行中的和弦名称和字素锚点，并可新增或删除歌词行和弦。文本编辑导致锚点进入替换范围时，系统会将其收拢到变更起点并标为低置信、待复核。指法查询先使用未转调谱包内的来源图；标准 EADGBE 定弦的其他可解析和弦使用内置 MIT 数据库的 828 个条目和 3,283 个按法，按低把位与低跨度选择默认图。没有匹配时显示“暂无指法”。

### 2.3 AI Agent Skill 与参考谱

`skills/chordsheet/` 已建立为合法 Codex Skill，要求 Agent 同时处理给定的复制文字、截图和 PDF，按“文字提供内容、截图优先位置、无截图时渲染 PDF”的规则建立谱包。它要求缺失标题或调弦时先询问用户，要求原始材料嵌入选择，并禁止从记忆生成指法。当前已提供 `public/downloads/chordsheet-builder-skill-v0.1.0.zip`：压缩包根目录为可安装的 `chordsheet/`，首页将其作为“下载制谱 Skill”提供。

`examples/the-cure-reference.chordsheet` 是不含原 PDF 的可导入参考包。它使用 C 书面调、Capo 1 和 Db 实际调，保存由用户提供 PDF 第 1 页逐一核验的 Asus2、Cmaj7、Fmaj7、Dm、F、C、G/B、G 八张指法。

## 4. 与 PRD 和实施方案的差异

当前实现没有删除或降低 PRD/实施方案中的正式要求；以下差异保留为待验收或待补齐事项：

1. The Cure 三页 PDF 的完整歌词、段落和锚点尚未由 Agent 生成并逐项人工确认；现有参考包只覆盖八张指法、Capo 和调性。
2. 编辑器尚未覆盖元数据、段落、纯和弦行、注释行以及段落/行的新建删除；编辑模式点击正文和弦仍切换全谱指法，而非选择该事件。
3. 谱包导出尚未提供用户界面来选择移除嵌入来源；当前保留已导入的来源字节。
4. 浏览器打印样式已实现，但尚未导出并逐页渲染真实 PDF 来确认所有分页、字体和裁切条件。
5. 多材料制谱由 Codex Skill 的 Agent 工作流承担，尚未实现可独立运行的多模态识别服务或完整材料端到端回归集合。

这些事项既不是已取消内容，也不是无条件延期；Simon 需要在验收时决定补齐、调整产品基线，或作为下一版本的明确范围。

## 5. 数据迁移、文档与上线事实

这是新建本地应用，没有要迁移的旧曲库或线上数据。IndexedDB 数据库名称为 `chordsheet-v1`；清除站点数据或更换浏览器前，用户需要导出 `.chordsheet` 备份。

本次按通用命名规则将版本文档统一为 `docs/versions/v0.1.0/` 下含版本号的文件名；旧目录与无版本文件名不再保留，PRD 与实施方案的内容没有删减。

内置指法库的第三方来源、MIT 许可和本地转换范围记录在 `THIRD_PARTY_NOTICES.md`；该数据不写入用户 `.chordsheet` 谱包。
