## 1. 文档用途与版本定位

v0.1.0 的产品基线继续有效，本文不重新定义数据契约、编辑与导入导出逻辑。除呈现层规则外，本文补充制谱 Skill 从 PDF、图片和保留布局的文字中恢复字素锚点的策略，以及对应的真实谱包测试基线。数据字段仍以 `schema/chordsheet.schema.json` 为准，模块划分仍以 `docs/versions/v0.1.0/implementation-v0.1.0.md` 为准。

本文明确替代或细化 v0.1.0 产品基线中的三处规则：

1. v0.1.0 PRD 第 8.4 节中「顶部和弦概览与正文同步切换为相同显示形态」的要求，由本文第 6 节的互补呈现规则替代；
2. v0.1.0 PRD 第 8.1 节中「不使用无用途动画」的边界，由本文第 5 节细化：功能性过渡动效被允许并定义，装饰性动画仍然禁止。
3. v0.1.0 PRD 第 5.3 节中仅要求保存字素偏移的制谱规则，由本文第 8.1 节细化为「和弦根音首字母对应到歌词具体字素」的必经步骤。

版本判定：本版本不新增能力模块、不改变技术基座或数据契约；字符级锚定是既有 `graphemeOffset` 契约的可靠性修复，按版本号规范仍属于修复版本（Z 段位），定为 v0.1.1。

## 2. 背景与要解决的问题

### 2.1 已暴露的呈现缺陷

v0.1.0 交付后在使用 The Cure 真实谱包时发现两个呈现缺陷。歌词行的和弦布局按「单行和弦名」设计：锚点是零宽零高的内联块，和弦按钮绝对定位，行上方仅预留约 1.8em 空间。全谱展开指法图后，约 58×100px 的指法图装入同一零占位按钮，向上溢出盖住上一行歌词与段落标题，相邻指法图水平互相重叠。此外，指法图下方的「来源已核验 / 内置指法库」小字在密集谱面中形成视觉噪音，且与指法图的纵向间距挤压了本已紧张的行内空间。

### 2.2 体验诊断

除缺陷外，当前界面在整体体验上存在以下问题，构成本版本改版的直接动因：

1. **工具栏比内容抢眼。** 顶栏四个按钮与三排工具栏胶囊均为同等重量的边框与文字，打开页面时视觉焦点落在控件上而不是歌名与谱面上，操作区压过了内容区；
2. **歌头信息没有主次。** 调性、Capo、定弦、速度四组标签与值使用同字号同重量的等宽体，演奏者高频查看的少数值（如实际调）没有与备查信息拉开层级；
3. **字阶阶梯过均匀。** 从展示级歌名到正文歌词之间缺少清楚的对比阶梯，段落标签与正文的区分度也偏弱；
4. **指法图模式下正文被推出首屏。** 顶部和弦概览与正文行内同时显示同一批指法图，信息重复，概览占位过大；
5. **状态切换生硬。** 展开/收起指法图、转调等状态变化瞬时完成，布局跳变缺乏过渡，界面缺少互动感。

### 2.3 设计方向

改版参考 Claude 式编辑气质：克制 chrome、内容先行、衬线排印、纸感细节、从容动效。具体到边界：

1. 不修改 `:root` 中任何颜色 token 的定义值，不引入新色相；允许使用既有 token 的透明度派生（例如 hover 时的极淡 accent 洗色）；
2. 复古浓度为中档：衬线排印、书版细节、极淡纸纹；不做做旧纸色、毛边、印章、打字机字体等强装饰；
3. 改动集中在样式层，不重构组件、不改变功能逻辑。

## 3. 版本范围

### 3.1 本版本交付

1. 行内指法图布局修复，并将布局行为固化为产品规则（第 7 节，已交付）；
2. 指法图可见来源标注移除（第 8 节，已交付）；
3. 视觉层级重构与复古排印（第 4 节）；
4. 过渡动效（第 5 节）；
5. 和弦概览互补呈现（第 6 节）。
6. PDF、图片与保留布局文本的和弦字符级锚定，以及 The Cure 完整谱包作为后续测试唯一默认基准（第 8.1 节）。

### 3.2 明确不交付

1. 不修改任何颜色 token 定义值；不做深色模式；
2. 不新增功能入口：概览折叠按钮、自动滚动、音频播放、和弦发声等均不在本版本；
3. 不做交错入场（stagger）、FLIP 布局动画等复杂动画；
4. 不改动 DOM 结构，唯一例外是为支持转调淡入给和弦符号文本节点增加 React `key`；
5. 不改变 `.chordsheet` 数据契约、本地存储、导入导出、编辑模式与转调 Capo 逻辑。

## 4. 视觉层级与排印规则

### 4.1 层级原则：chrome 退后、内容先行

页面唯一的高对比主表面是谱面纸张。顶栏、工具栏、侧栏属于操作层，应退为背景：

1. 顶栏全部操作按钮（含「编辑」）统一为细边框 quiet 风格；「编辑」的激活态用 accent 边框与文字表达，不再使用实心底色；顶栏取消大面积软阴影，仅保留 1px 底部分隔线；毛玻璃与粘性定位保留；
2. 工具栏三组控件（转调、Capo、显示与字号）去除胶囊容器，直接排在画布上，组间以 1px 竖细线分隔，组内标签降为安静小字；整组视觉重量低于谱面内容；移动端取消分隔线、自然换行；
3. 侧栏保持现有细边线与半透明材质，曲目列表样式不变。

### 4.2 三级字阶与注脚

| 层级 | 对象 | 规则 |
|---|---|---|
| 展示级 | 歌名 | 维持现有衬线大标题（字族、字号、字距不变） |
| 章节级 | 段落标签（VERSE 1 等） | `font-variant-caps: all-small-caps`，字距加宽至约 .16em，颜色保持 accent |
| 正文级 | 歌词正文 | 字族改为衬线（与标题同一 serif 字栈），字号与行距维持现状 |
| 注脚级 | 辅助说明、元信息标签 | 整体降半档：颜色更浅、字重更轻 |

### 4.3 歌头元信息

歌头元信息（调性、Capo、定弦、速度）的值由等宽体改为衬线，并启用旧式数字（`font-variant-numeric: oldstyle-nums`），标签颜色降为 `--quiet`。工具栏中的「实际调」维持现有 accent 提亮不变。和弦名与指法图内的标注文字保持等宽体不变，与衬线歌词形成「记谱法 vs 文学文本」的对比。

### 4.4 质感细节

谱面纸张叠加一层极淡的 SVG 颗粒纹理（feTurbulence 生成的灰度噪点，平铺、低不透明度），近看有纸感，远看仅呈现温度。歌曲标题下方的分隔由单粗线改为书版双线：2px 主线加一条间隔约 3px 的 1px 副线。打印时去除纸纹，双线保留。

## 5. 过渡动效规则

### 5.1 动效原则

动效只服务于状态理解，不制造装饰性趣味。全部动效时长在 160–300ms 之间，使用统一的缓出曲线；只做 `transform` 与 `opacity` 动画，不引发布局抖动。明确不做交错入场、FLIP 动画、自动滚动与离场动画。

### 5.2 具体动效

| 动效 | 触发 | 表现 | 时长 |
|---|---|---|---|
| 谱面呼吸 | 切换全谱指法显示 | 锚点槽位高度平滑过渡，谱面缓缓撑开或收拢；拥挤槽位的宽度修正即时生效，不做动画 | 约 280ms |
| 指法图入场 | 指法图挂载 | 淡入并轻微上浮，如印章落纸 | 约 220ms |
| 转调淡入 | 转调导致符号变化 | 新和弦符号淡入 | 约 160ms |
| 悬停反馈 | 悬停正文和弦 | 背景出现极淡 accent 洗色 | 约 120ms |
| 悬停反馈 | 悬停概览指法图 | 轻微上浮并加深阴影 | 约 160ms |

### 5.3 降级与打印

`prefers-reduced-motion` 下全部动效关闭，由现有全局媒体查询统一覆盖，不单独为每个动效写降级。打印页面不触发任何动画，也不残留过渡中的中间状态。

## 6. 和弦概览互补呈现

全谱指法显示的两个状态中，顶部和弦概览与正文改为互补关系：

| 全谱指法显示 | 正文 | 顶部和弦概览 |
|---|---|---|
| `name` | 和弦名 | 指法图网格（本曲和弦的唯一图示入口） |
| `nameAndDiagram` | 每个和弦显示指法图 | 收缩为单行和弦名列表 |

任何时刻「名称」与「指法图」都各有一处可查；展开指法后概览自动让位，正文第一行进入首屏。全局开关的语义与入口不变：点击正文任意和弦、概览头和工具栏的同一按钮仍然切换全谱状态，按钮文案不变。本规则替代 v0.1.0 PRD 第 8.4 节中概览与正文同步显示相同形态的要求。

## 7. 行内指法图布局规则（已修复并固化）

以下规则已成为布局基线，替代「为单行和弦名预留空间」的旧实现假设：

1. 歌词在名称与指法图两种模式下都保持连续排版，锚点默认零占位，不为指法图统一撑开歌词；
2. 指法图模式下，每个含和弦锚点的视觉行由锚点槽位自身的高度（约 7.2em）独立预留图示空间，歌词窄屏换行后每个视觉行都有同等空间；指法图以其锚点为中心水平居中；
3. 相邻锚点中心距小于指法图宽度加间隔（64px）时，仅撑宽前一个锚点的槽位至刚好不重叠，其余位置不受影响；
4. 任意视口宽度与字号下，不得出现指法图之间、指法图与段落标题、指法图与其他视觉行歌词的重叠。

## 8. 指法图来源标注规则

指法图下方不再显示可见的来源小字（「来源已核验」「内置指法库」）。数据层面对指法来源的要求不变：仍然只渲染核验状态为 `verified` 的指法，缺少已核验指法时显示「暂无指法」；指法图的无障碍标签继续携带核验来源信息，供辅助技术读取。

### 8.1 制谱字符级锚定与测试基准

对 PDF 或截图，制谱过程必须先将页面渲染为图片，并把每个和弦根音首字母的左边缘映射到同一歌词行中具体字素之前的边界；不得先吸附到单词开头、空格或估算列。保留和弦行与歌词行排版的纯文本同样在清理空白前按同列字符完成映射。视觉位置不清晰时才允许推断，并以 `low` / `unreviewed` 记录原因。

The Cure 的完整测试基准固定为 `output/the-cure-test-run/the-cure-olivia-rodrigo.character-anchor-test.chordsheet`。它由三页原 PDF 渲染图逐字符核对，包含 11 个段落、49 行、94 个和弦事件且不嵌入原 PDF；其中 1 行因 PDF 内视觉相同的非 ASCII `e` 被规范化，保留低置信内容冲突标记。自本版本起，所有新增或修改的单元、组件、端到端、视觉和人工回归测试均以此谱包为输入，不再以演示谱或旧 The Cure 参考包作为测试基准。

## 9. 验收标准

### 9.1 布局验收

1. 导入 The Cure 谱包并展开全谱指法图后，行内指法图之间、指法图与段落标题、指法图与其他歌词行文字均零重叠；
2. 歌词保持连续排版，仅间距不足的锚点被撑宽（The Cure 实测不超过 10 处）；
3. 名称模式布局与 v0.1.0 一致，无回归。

### 9.2 呈现验收

4. `name` 模式下概览显示指法图网格，`nameAndDiagram` 模式下概览收缩为单行和弦名；
5. 歌词为衬线，段落标签为小型大写，歌头元信息为衬线旧式数字，歌头为书版双线，谱纸可见极淡纸纹；
6. `:root` 全部颜色 token 定义值与 v0.1.0 逐一相同；
7. 指法图无可见来源小字，其无障碍标签包含来源信息；
8. 顶栏与工具栏按钮均为细边框风格，本版本不再保留实心底色按钮；工具栏无胶囊容器。

### 9.3 动效验收

9. 切换全谱指法显示时行高与槽位宽度平滑过渡，无瞬时跳变；转调后新符号淡入；
10. 开启 `prefers-reduced-motion` 后全部动效关闭；
11. 打印预览中无纸纹、保留双线、无动画中间态。

### 9.4 工程验收

12. `npm run test:run` 全部通过；`npm run test:e2e` 桌面与手机项目通过（含更新后的概览断言）；
13. 移动端视口（375px）展开指法图后无横向溢出。
14. 所有测试入口均加载第 8.1 节指定的 The Cure 包；校验、导入、阅读、编辑、转调、Capo、指法、导出与视觉回归不得切回演示谱或旧参考包。

## 10. 已知风险与完成条件

| 风险 | 处理原则 |
|---|---|
| 衬线字族改变歌词宽度，影响锚点间距 | 行内布局为运行时实测，与字族无关；由验收第 1–2 条兜底 |
| 纸纹在低质量屏幕或打印机上表现异常 | 不透明度极低；打印时移除 |
| 概览互补改变既有使用习惯 | 全局开关语义与入口不变；概览信息不减少，只换位 |
| 动画在低端设备掉帧 | 仅 `transform`/`opacity`，时长不超过 300ms，可随时整体关闭 |
| PDF/OCR 将和弦吸附到词首而非实际字符 | 将根音首字母映射到具体字素；不清晰时低置信，不用词级猜测伪装为确认 |

本版本只有在第 9 节全部验收通过、Release 记录实际交付与偏差后，才由 Simon 决定是否标记完成。
