# 有谱么新版导入适配

| 项目 | 说明 |
|---|---|
| 状态 | implemented，真实书签点击验收待完成 |
| 检查日期 | 2026-10-10 |
| 文档职责 | 当前适配协议、操作步骤和验证边界 |

## 1. 协议变化及适配方式

用户提供的两份真实复制样本在 `_XHE_COPY_PASTE_SENTINEL_` 后分别带随机标识。检查有谱么当前编辑器脚本 [dt-editor.es.ac4f5f2f.js](https://cdn.yopu.co/js/dt-editor.es.ac4f5f2f.js) 后，确认复制会把 `{ stamp, itemList }` 写入有谱么域名的 `localStorage["user-data-xhe-copy"]`，只把哨兵与 stamp 放入纯文本剪贴板。粘贴通过匹配 stamp 取回 itemList；标识不匹配则提示复制内容失效，不再把哨兵后的 JSON 当作节点数组。

ChordSheet 的跨域页面无法写入这项同源缓存。因此当前实现移除旧版复制入口、JSON 剪贴板载荷和权限失败文本框，改为生成自包含的导入书签。节点转换仍保留段落、逻辑行、当前转调和字素级锚点。

## 2. 用户操作与边界

1. 在 ChordSheet 打开谱包，点击“导入到有谱么”。
2. 把生成的歌曲导入按钮拖到 Chrome 书签栏；macOS 可用 ⌘⇧B 显示书签栏。
3. 打开有谱么空白草稿页，点击书签。书签在该页面写入新版缓存，向编辑器发送 `beforeinput` / `insertFromPaste` 输入事件，直接插入谱面，无需手工复制粘贴。
4. 核对段落、歌词、和弦名称及字符落点；标题、歌手、Capo 等未传递项按页面提示另行设置。

书签保存生成当时的谱面快照，修改或转调后需要重新生成。已有草稿会提示确认追加到末尾，不替换原内容。书签只允许在 `https://yopu.co/draft` 上运行，要求唯一编辑器及可识别的末尾文本节点，不发起网络请求、不投稿。第三方编辑器自身可能自动保存导入结果。

## 3. 实现与验证

领域转换器为 `src/domain/yopuImport.ts`；UI 展示可拖动书签和损失项，点击本地链接只显示操作提示，不执行书签。书签在目标页面生成新 stamp，将完整节点写入本地缓存，并把光标放在末尾的 `[text-value]` 文本节点；不能把选区放在编辑器根元素上，因为第三方编辑器会拒绝这种选区。

版本交付、测试结果和真实验收状态见 [v0.2.1 交付记录](../versions/v0.2.1/release-v0.2.1.md)。

本地测试覆盖完整 The Cure 基准谱节点往返、Unicode 锚点、转调、新版缓存与输入事件、错误域名、已有内容取消、存储失败及 UI 操作。浏览器 E2E 覆盖书签生成和旧入口移除；这些验证不能替代真实编辑器验收。

真实网页检查已确认剪贴板仅有纯文本、缓存读取协议及编辑器末尾节点结构。仍需使用完整 The Cure 基准谱，在真实编辑器中执行书签安装与点击，核对段落、换行、歌词、和弦名称及落点，并重新复制验证节点语义一致；本地测试不能证明第三方编辑器兼容。

历史 `v0.2.0` 文档保留已发布版本事实；自 `v0.2.1` 起，有谱么适配以本文为准。
